# 모델 학습 계획 (자유 생성 모델, free-v1)

### *참고* 이미 d는 128 l은 4이다(위에 나온 모든 실험이 그렇다)

###### 작성일: 2026-11-02

## 1. 한눈에 보기

- **지금**: 60000스텝 모델의 hold-out 결론줄이 79.5%예요 (30000스텝 때 59.5%).
- **바로 다음**: 고친 `gen_reason.js`, `train_free.js`를 넣고, 처음부터 60000스텝을 새로 학습(`gen2-60k`)해서 비교해요.
- **그다음**: 좋아졌으면 `promote`로 사이트에 올려 직접 써 보고, 남은 약점(cmp·cond)을 한 번에 하나씩 고쳐요.
- **원칙**: 한 번에 하나만 바꾸고, 같은 평가 문제로 비교해요.

## 2. 현재 상태 (기준선)

| hold-out 결론줄 | 30000스텝 | 60000스텝 |
|---|---|---|
| 전체 | 59.5% | 79.5% |
| isa | 84.1% | 96.2% |
| prop | 88.7% | 92.8% |
| cmp | 26.0% | 59.7% |
| cond | 19.2% | 57.7% |

- 본 문제(train) 99%, brain 암기 100%, 모름(OOD) 100%예요.
- cmp 판정 정확도는 84.9% (101/119)예요.
- cond는 결론이 58% 맞는데 완전일치는 25%예요.
- 두 실행의 데이터 통계가 같았어요. 바뀐 건 스텝 수뿐이라, 30000스텝 때의 낮은 점수는 학습이 덜 된 탓이었어요.

## 3. 남은 문제 (우선순위 순)

1. **긴 단어가 잘려요.** "쏘가리"가 "쏘", "카메라"가 "카메", "야자나무"가 "야, 야자나무"로 나와요. 무작위 단어가 2~3글자뿐이었고 조사 글자가 단어에 안 들어갔던 것이 원인으로 보여요 (추정).
2. **cond의 근거 줄이 깨져요.** "가뭄이 들는다"처럼 서술어 활용이 틀려요. 사이트에서는 이 줄이 그대로 보여요.
3. **cmp에서 방향이 뒤집혀요.** "리모컨은 열쇠보다 싸다. 열쇠는 리모컨보다 비싸?"에 "아니야"라고 답해요.

## 5. 1차 실험: gen2-60k

### 5.1 짧은 시험 실행 (권장)

본 실행 전에 짧게 한 번 돌려서, 새 코드가 끝까지 도는지 확인해요. `train_free.js` 변경은 실제 학습 환경에서 아직 돌려 보지 못했어요.

| 입력 | 값 |
|---|---|
| name | `smoke1` |
| steps | `200` |
| gen_n | `3000` |
| 나머지 | 기본값 |

확인할 것은 세 가지예요.
- 워크플로가 에러 없이 끝나는지
- `gen.log`에 `wordGuard`, `josaKept`가 찍히는지
- `train.log` 마지막에 평가표가 나오는지

### 5.2 본 실행

| 입력 | 값 | 이유 |
|---|---|---|
| name | `gen2-60k` | 이름이 이미 있으면 워크플로가 멈춰요 |
| steps | `60000` | 지난번과 같은 조건 |
| D / L | `128` / `4` | 그대로 |
| lr | `1.5e-3` | 그대로 |
| gen_n | `60000` | 그대로 |
| gen_seed | `7` | 바꾸면 평가 문제도 바뀌어서 비교가 흐려져요 (8절 참고) |
| merges | `300` | 그대로 |
| resume_from | 비움 | 단어와 데이터가 크게 바뀌었으니 처음부터 |
| activate | `false` | 비교한 뒤 `promote`로 올려요 |

### 5.3 시작 직후 확인

`gen.log`는 `reason_stats.json`에도 들어 있어요. 지난 실행의 기록은 저장소 `train_data/runs/<이전 이름>/`에 있어요.

- **`wordGuard`**: 조사 글자가 든 단어를 교사(lm.js)가 못 읽어서 버려진 개수예요. kept에 비해 크면(예: 20% 넘으면) 교사 쪽 문제예요. 6절의 대응을 따르세요.
- **`josaKept`**: 0보다 커야 해요. 0이면 조사 글자 든 단어가 학습에 안 들어간 거예요.
- **`_wlen`**: 무작위 단어 길이 분포예요. 2~5가 모두 보여야 해요.
- **`noTeacher`, `mismatch`**: 지난 실행의 값과 비교해서 크게 늘지 않았는지 보세요.
- **생성 개수**: 요청한 60000개에 가까워야 해요 (부족하면 경고가 떠요).
- **`train.log`의 `T`와 `T 초과로 제외`**: 단어가 길어져서 `T`가 커지거나 제외가 늘 수 있어요.
- **`step/s`와 `남은 시간`**: 워크플로 제한이 340분이에요. 예상이 그 안에 안 들어오면 6절의 시간 초과 대응을 따르세요.

## 6. 평가와 판단 기준

아래 목표치는 제가 제안한 값이에요. 정해진 기준이 아니니 상황에 맞게 조정하세요.

| 지표 | 기준선 | 목표(제안) |
|---|---|---|
| hold-out 결론줄 전체 | 79.5% | 85% 이상 (79.5% 미만이면 승격 보류) |
| cmp 결론줄 | 59.7% | 70% 이상 |
| cond 결론줄 / 완전일치 | 57.7% / 25% | 70% 이상 / 45% 이상 |
| 틀린 예 중 단어 잘림 | 14개 중 4개 | 거의 없음 |
| train / brain / OOD | 99% / 100% / 100% | 유지 (떨어지면 회귀) |

- 유형별 평가 문제가 80~120개 정도라서, 약 10%p 안쪽의 차이는 우연일 수 있어요 (추정).
- 평가 결과는 `train_data/runs/gen2-60k/free_eval.json`과 `train_log.txt`에 남아요.

### 결과별 대응

| 결과 | 다음 행동 |
|---|---|
| 전체가 좋아지고 단어 잘림도 줄었다 | 7절로 가서 `promote` |
| 단어 잘림만 해결되고 cmp·cond는 그대로다 | 8절의 A, D 중 하나를 실험 |
| train·brain·OOD가 떨어졌다 | 새 데이터나 복사 과제가 다른 학습을 방해한 것이에요. 원인을 나눠서 다시 실험(생성기만 바꾼 실행과 비교) |
| `wordGuard`가 너무 크다 | `gen_reason.js`의 조사 글자 삽입 확률(`R.chance(.12)`)을 낮추거나, 교사가 그런 단어를 읽도록 `lm.js`를 확인 |
| 시간 초과가 예상된다 | steps를 줄이거나, 두 번에 나눠서(예: 40000 + 이어 학습) 실행 |

## 7. 승격 (사이트에서 쓰기)

1. GitHub Actions에서 `promote`를 실행하고 name에 `gen2-60k`를 넣어요.
2. 실행 요약에서 `steps`와 `loss`가 맞는지 확인해요.
3. 사이트의 ⚖️ 둘 다 비교 모드에서 실제 질문으로 확인해요. 쏘가리·카메라처럼 긴 단어, 조건 문제, 비교 문제를 꼭 넣어 보세요.
4. 마음에 안 들면 이전에 쓰던 모델의 이름으로 다시 `promote`하면 돌아가요.
5. 이전 활성 모델은 Hugging Face의 `previous/before-이름-실행번호/`에 백업돼요. `runs/`에 없던 모델이라면 이 백업을 웹에서 직접 복사해서 되돌려야 해요.
6. 현재 활성인 실행 이름은 저장소의 `train_data/ACTIVE.txt`에 남아요.

## 8. 다음 실험 후보

1차 결과를 보고 **하나씩** 골라요.

| 후보 | 바꿀 것 | 메모 |
|---|---|---|
| **A. cmp 비중 올리기** | `--cmpw` 0.4에서 0.5 정도로 | 워크플로에는 `cmpw` 입력이 없어서 추가가 필요해요 |
| **B. 더 오래 학습** | 같은 모델을 `resume_from: gen2-60k`로 이어 학습 | 크기(D, L, merges)는 옛 값이 유지돼요. 30000에서 60000으로 20%p 올랐으니 아직 여지가 있을 수 있어요 (추정) |
| **C. 모델 키우기** | D=128, L=4, lr=1.5e-3, 처음부터 | 워크플로 안내문의 권장값이에요. 느려지니 시간 제한을 꼭 확인하세요 |
| **D. cond 서술어 보강** | `gen_reason.js`의 학습용 서술어(VERB) 확대, 활용이 어려운 서술어(ㄹ 받침 등) 비중 | 새 서술어의 활용을 모델이 직접 써야 해서 약한 것으로 보여요 (추정). `mismatch` 통계로 교사가 풀 수 있는지 먼저 확인해야 해요 |
| **E. 데이터 늘리기** | `gen_n` 60000에서 100000 정도로 | 시간이 늘어요 |

- B와 같이 `gen_seed`를 바꾸면 **평가 문제도 바뀌어요.** (평가 세트는 `gen_seed + 1`로 만들어져요.) 정확한 비교가 필요하면 `gen_seed`는 7로 유지하세요.
- 평가는 같은 `n`(기본 400)으로 비교하세요.
