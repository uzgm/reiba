# BAREA 학습 확장 가이드

학습을 한 번 끝낸 뒤, **다른 종류의 질문**을 더 배우게 하고 싶을 때 보는 가이드예요. 어떤 파일을 고치는지, 그리고 `model_free.json`이 **덮어써지지 않게** 하는 방법을 적었어요.

## 0. 먼저 알아둘 것

- 이 가이드는 `gen_reason.js`, `train_free.js`, `lm.js`의 안쪽 코드를 직접 보지 않고, 지금까지의 로그와 동작을 보고 쓴 부분이 있어요. 아래 **"확인 명령"** 으로 실제 이름을 먼저 확인하세요.
- 질문을 두 종류로 나눠서 생각하세요.
  - **사실 질문** ("소수가 뭐야" 같은 것): `data/` 폴더에 JSON만 추가하면 돼요. **학습이 필요 없어요.**
  - **추론 질문** ("A보다 B가 크다 … 누가 제일 커?" 같은 것): 새 유형이면 코드를 고치고 **다시 학습**해야 해요. 2번부터 보세요.

## 1. 파일 역할

| 파일 | 하는 일 |
|---|---|
| `data/*.json` | 사실 지식. 사이트가 읽어서 검색으로 답해요 |
| `gen_reason.js` | 추론 학습 문제를 만들어요 → `data/reason_*.jsonl` |
| `train_free.js` | 그 문제로 학습해서 `model_free.json`을 만들어요 |
| `lm.js` | 정답을 계산하는 "도구"와 토크나이저. 학습과 사이트가 같이 써요 |
| `index.html` | 화면. 신경망 답과 도구 답을 비교해서 점수를 보여줘요 |
| `train_data/model_free.json` | **사이트가 읽는 현재 모델** (활성 모델) |
| `train_data/runs/이름/` | 학습할 때마다 따로 보관하는 결과 (5번 참고) |

## 2. 새 추론 유형을 가르칠 때 고칠 파일 (순서대로)

예: "시간 순서 문제", "포함 관계 문제" 같은 새 유형을 추가한다고 해요.

1. **`lm.js` — 정답 계산(도구)에 새 유형을 추가해요.**
   정답을 만드는 기준이에요. 학습 문제의 답도, 사이트의 "도구와 일치" 점수도 이 기준을 써요. 이쪽이 틀리면 전부 틀려요.
2. **`gen_reason.js` — 새 유형 문제를 만드는 부분을 추가해요.**
   기존 유형 생성 코드는 지우지 말고, 새 유형을 **옆에 더하세요.** 기존 유형 비율이 너무 줄면 예전 것을 잊어요.
3. **`train_free.js` — 보통은 안 고쳐요.** 아래 경우에만 확인하세요.
   - 로그의 `T 초과로 제외`가 늘었다면 문장이 너무 길어진 거예요. 문제를 짧게 만들거나 최대 길이(`T`)를 늘려야 해요. 모델이 커져서 메모리를 더 써요.
   - 어휘 수(`V=`)가 크게 늘면 모델 크기(`--D`, `--L`)를 키우는 걸 고려하세요.
4. **`index.html` — 새 답 형식이 생겼을 때만 고쳐요.**
   `headKind()` 함수가 답의 첫 줄로 결론 종류(응/아니야/모름 등)를 나눠요. 새 답 형식이 이 틀에 안 맞으면 여기에 추가해야 점수가 맞게 나와요. 예시 질문 칩(`SAMPLES`)도 같이 더하면 좋아요.

**확인 명령** (Codespace 터미널)
```bash
grep -n "function\|=> *{" gen_reason.js | head -40     # 문제 생성 함수 이름
grep -n "tools" lm.js | head -20                       # 정답 도구 위치
grep -n "process.argv\|opt\b" train_free.js | head -20 # 쓸 수 있는 옵션
```

## 3. 새 주제 학습 순서

1. **지금 학습 데이터를 백업해요.** (4번)
2. 위 2번대로 코드를 고쳐요.
3. Codespace에서 `gen_reason.js`로 새 데이터를 만들어요. 실행 방법(인자)은 파일 맨 위 설명을 보세요. 만든 `data/reason_*.jsonl`은 `git add -f`로 올려요.
4. 작게 먼저 테스트해요. 에러가 없는지만 보는 용도예요.
   `--steps 200 --D 32 --L 1`
5. 본 학습을 돌려요. **이름을 붙이고, 활성화는 끄고** 돌려요. (5번)
6. 평가 점수와 사이트의 "누적 일치"를 봐요. 좋아졌을 때만 활성화해요.

**처음부터 학습 vs 이어서 학습**
- 새 데이터에 **옛 데이터를 섞어서** 학습하면 옛 유형을 안 잊어요. 가장 안전해요.
- 새 데이터만으로 `--resume`을 하면 옛 유형을 잊어버릴 수 있어요. 이때는 점수를 꼭 비교하세요.
- 모델 크기(`--D`, `--L`)를 바꾸면 이어하기(`--resume`)가 안 돼요. 처음부터 해야 해요.

## 4. 학습 데이터 덮어쓰기 막기

`gen_reason.js`를 다시 돌리면 `data/reason_train.jsonl` 같은 파일이 **새로 덮어써질 수 있어요.** 돌리기 전에 복사해 두세요.

```bash
mkdir -p train_data/datasets/v1
cp data/reason_train.jsonl data/reason_eval.jsonl train_data/datasets/v1/
git add -f train_data/datasets
git commit -m "학습 데이터 v1 보관"
git push
```

- 새 데이터를 만들 때마다 `v2`, `v3`처럼 번호를 올려요.
- `train_data/datasets/`의 `.jsonl`은 사이트가 지식으로 읽지 않아요. (사이트는 `data/`의 `.json`만 읽어요.)

## 5. model_free.json 덮어쓰기 막기

원칙은 세 가지예요.

1. **학습 결과는 항상 `train_data/runs/이름/`에 따로 저장해요.** 이름이 이미 있으면 학습 시작 전에 멈춰요. 한 시간을 쓰고 나서 실패하지 않아요.
2. **사이트가 읽는 `train_data/model_free.json`은 `activate`를 켰을 때만 바뀌어요.** 기본값은 꺼짐이라서, 실험으로 돌려도 사이트의 모델은 그대로예요.
3. 이전 모델은 `runs/` 안에 남아 있어서 언제든 되돌릴 수 있어요.

### 워크플로 (`.github/workflows/train.yml` 전체 교체)

```yaml
name: train
on:
  workflow_dispatch:
    inputs:
      name:
        description: 결과 이름 (영문/숫자만, 비우면 run-번호)
        default: ""
      steps:
        description: 학습 스텝
        default: "20000"
      D:
        description: 모델 폭(D)
        default: "96"
      L:
        description: 층 수(L)
        default: "3"
      resume_from:
        description: 이어서 학습할 모델 (active = 현재 활성 모델, 비우면 처음부터)
        default: ""
      activate:
        description: 끝나면 사이트가 읽는 모델로 바꾸기
        type: boolean
        default: false
permissions:
  contents: write
jobs:
  train:
    runs-on: ubuntu-latest
    timeout-minutes: 340
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install
      - name: 학습
        shell: bash
        env:
          NAME_IN: ${{ inputs.name }}
          STEPS: ${{ inputs.steps }}
          DD: ${{ inputs.D }}
          LL: ${{ inputs.L }}
          RESUME_FROM: ${{ inputs.resume_from }}
        run: |
          NAME=$(printf '%s' "${NAME_IN:-run-$GITHUB_RUN_NUMBER}" | tr -c 'A-Za-z0-9._-' '_')
          if [ -e "train_data/runs/$NAME" ]; then
            echo "이미 있는 이름이에요: $NAME (덮어쓰지 않고 멈춰요)"; exit 1
          fi
          echo "NAME=$NAME" >> "$GITHUB_ENV"
          ARGS="--steps $STEPS --D $DD --L $LL"
          if [ -n "$RESUME_FROM" ]; then
            SRC="$RESUME_FROM"; [ "$RESUME_FROM" = "active" ] && SRC=train_data/model_free.json
            [ -f "$SRC" ] || { echo "없는 파일: $SRC"; exit 1; }
            cp "$SRC" /tmp/base.json
            ARGS="$ARGS --resume /tmp/base.json"
          fi
          rm -f model_free.json
          echo "$ARGS" > args.txt
          node train_free.js train $ARGS 2>&1 | tee train.log
      - name: 보관하고 올리기
        shell: bash
        env:
          ACTIVATE: ${{ inputs.activate }}
        run: |
          D="train_data/runs/$NAME"
          mkdir -p "$D"
          cp model_free.json "$D/model_free.json"
          cp train.log "$D/train_log.txt"
          cp args.txt "$D/args.txt"
          if [ "$ACTIVATE" = "true" ]; then
            cp model_free.json train_data/model_free.json
          fi
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add train_data
          git commit -m "train: $NAME"
          git pull --rebase
          git push
```

### 쓰는 법

| 하고 싶은 것 | 입력 |
|---|---|
| 실험으로 돌려 보기 | `name`만 적고 `activate` 끔 |
| 마음에 들면 사이트에 적용 | 3번에서 설명 |
| 현재 모델에서 이어서 더 학습 | `resume_from`에 `active` |
| 특정 결과에서 이어서 | `resume_from`에 `train_data/runs/이름/model_free.json` |

### 마음에 든 결과를 사이트에 적용하는 법

**방법 A. 같은 이름으로 다시 돌리지 말고, 파일을 복사해요.** 레포 웹에서
`train_data/runs/이름/model_free.json`을 열고 **Raw → 내용 복사**, 그다음 `train_data/model_free.json`을 열어서 연필 아이콘으로 붙여 넣고 Commit 해요. (파일이 커서 폰에서 어려우면 방법 B)

**방법 B. Codespace 터미널에서**
```bash
git pull
cp train_data/runs/이름/model_free.json train_data/model_free.json
git add train_data/model_free.json
git commit -m "활성 모델: 이름"
git push
```

## 6. 되돌리기

- 이전 결과는 `train_data/runs/` 안에 다 있어요. 위 5번의 복사 방법으로 되돌려요.
- `runs/`에 없는 예전 파일도 git 기록에 남아 있어요.
  ```bash
  git log --oneline -- train_data/model_free.json
  git checkout 커밋번호 -- train_data/model_free.json
  ```

## 7. 막힐 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `이미 있는 이름이에요` | 같은 `name`을 또 썼어요 | 다른 이름으로 다시 실행해요 |
| `없는 파일: ...` | `resume_from` 경로가 틀렸어요 | 레포 웹에서 경로를 확인해요 |
| `cp: model_free.json: No such file` | 학습이 저장을 못 했어요 | 학습 단계 로그의 빨간 줄을 확인해요 |
| push가 거절돼요 | 동시에 두 번 돌렸어요 | 한 번에 하나씩만 돌려요 |
| 사이트가 안 바뀌어요 | `activate`를 꺼서 활성 모델이 그대로예요 | 5번의 적용 방법을 해요 |
| 이어하기가 에러 | 모델 크기(`D`, `L`)를 바꿨어요 | `resume_from`을 비우고 처음부터 해요 |

## 8. 아직 못 정한 것

- 사이트에서 모델을 **고르는** 기능(활성 모델 말고 `runs/`의 다른 모델 불러오기)은 아직 없어요. 필요하면 `index.html`의 모델 선택 메뉴에 붙일 수 있어요.
- 2번의 구체적인 함수 이름과 수정 위치는 `gen_reason.js`, `train_free.js`, `lm.js`를 직접 보면 정확히 적을 수 있어요. 이 세 파일을 보내 주면 가이드의 2번을 실제 코드 기준으로 고쳐 드릴 수 있어요.
